# Phase 9 — UI Design Contract

> Visual and interaction contract for Timer UI & Admin Controls. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase **extends existing shipped components** rather than introducing new design primitives. The contract below pins down (a) the resolution of the one open question from `09-CONTEXT.md`, (b) exact per-phase color tokens + labels, (c) the new "80+20" preset and "Start Timer" affordances, and (d) the not-started timer card state. All values are pinned to the established `@theme` tokens in `src/app.css`.

---

## Open Question Resolution (REQUIRED by 09-CONTEXT.md)

**Question:** Does the flat per-phase color treatment REPLACE the existing within-period urgency progression for the main phase of all timers, or apply flat treatment only to the new phases?

**Resolution: Option 1 — no regression.**

- The **main** phase keeps its existing within-period urgency progression (`normal → warning <10m → danger <5m`) for BOTH plain 60/90/120 timers AND the 80+20 main period. This is the already-shipped behavior in `src/components/TimerDisplay.tsx` (`urgencyStyles`) and `src/hooks/useCountdown.ts` (`computeUrgency`).
- The **overtime** and **count-up** phases get a **flat, single distinct color per phase** (no internal progression), keyed off `useCountdown().phase`.

**Rationale:**
1. The locked design intent ("flat distinct color per phase") was explicitly about making the three NEW 80+20 phases distinguishable — not about flattening the urgency cue that already helps players on plain timers.
2. Removing the `<10m` / `<5m` progression from the main phase would silently change shipped 60/90/120 timer behavior with zero requirement asking for it (regression risk called out in `09-CONTEXT.md`).
3. The amber overtime band sits between two reds (main-danger and count-up-overrun), visually breaking them up, so distinctness is preserved without flattening main. Phase label + `+M:SS` prefix further disambiguate.

`useCountdown` already maps `overtime → urgency 'danger'` and `countup → urgency 'expired'`. Phase 9 must make `TimerDisplay` select its band style from **`phase` first**, falling back to the `urgency` progression only when `phase === 'main'`. Do NOT continue keying the whole card off `urgency` alone.

## Spacing Scale

Declared values (all multiples of 4), reflecting the tokens already in use across `TimerDisplay`, `TimerControls`, `AdminControls`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), tight insets |
| sm | 8px | Button row gaps (`gap-2`), control spacing |
| lg | 16px | Card padding (`p-4`), control row gaps (`mb-4`) |
| xl | 24px | Panel bottom margin (`mb-6`) |

> Inherited note: the existing components use Tailwind `spacing-3` (12px) for `mb-3`/`mt-3`/`py-3` internal rhythm. Phase 9 declares no new 12px usages, so 12px is intentionally omitted from the named scale above; existing `spacing-3` usages are left untouched.

Exceptions:
- `min-h-[44px]` — primary/control touch targets (Start Timer, pause/resume/+5/cancel, Generate). Accessibility minimum, retained.
- `min-h-[36px]` — compact duration preset chips (60/90/120/80+20). Retained from existing picker.

## Color

60/30/10 split, pinned to `src/app.css` `@theme` tokens (dark MTG-inspired palette):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-surface` `#0f0a1a` | Page background behind cards |
| Secondary (30%) | `--color-surface-raised` `#1a1128` (+ `--color-surface-overlay` `#241a35`) | Timer card, admin panel, neutral control buttons |
| Accent (10%) | `--color-accent` `#f59e0b` (`--color-accent-bright` `#fbbf24` hover) | see reserved-for list |
| Destructive | `--color-error` `#ef4444` | Cancel Timer, End Event, main-danger band, count-up overrun band |

Accent reserved for (explicit — never "all interactive elements"):
- The **selected** duration preset chip (including the new `80+20`).
- The **"Generate Next Round"** primary button.
- The **"Start Timer"** primary button (the new explicit-start CTA).
- The **OVERTIME** phase timer band (`bg-accent/15 border-accent text-accent-bright`).
- The notification **"Enable"** affordance (existing).

Neutral (NOT accent): pause / resume / +5 min buttons use `bg-surface-raised border-border` — they are secondary controls, not accent-worthy.

### Per-Phase Timer Band Tokens (the core of this phase)

`TimerDisplay` selects the band by `countdown.phase`; for `main` it then selects by `countdown.urgency`. Add `data-phase={countdown.phase}` to the `timer-display` element for E2E assertions.

| Phase | Treatment | Tailwind band classes | Status label | Numeral format |
|-------|-----------|-----------------------|--------------|----------------|
| `main` — normal (>10m) | urgency progression (kept) | `bg-surface-raised text-text-primary border-border` | `ROUND TIMER` | `M:SS` |
| `main` — warning (≤10m) | urgency progression (kept) | `bg-yellow-900/30 text-yellow-400 border-yellow-700` | `ROUND TIMER` | `M:SS` |
| `main` — danger (≤5m) | urgency progression (kept) | `bg-red-900/30 text-red-400 border-red-700` | `ROUND TIMER` | `M:SS` |
| `overtime` | flat amber, single color, no progression | `bg-accent/15 text-accent-bright border-accent` | `OVERTIME` | `M:SS` (counting down) |
| `countup` | flat red + pulse | `bg-red-900/50 text-red-300 border-red-500 animate-pulse` | `OVERRUN` | `+M:SS` (counting up) |
| any phase, `isPaused` | dim the active band | active band classes + `opacity-70` | `PAUSED` | frozen value |

Notes:
- Labels follow the locked decision (`OVERTIME` / `OVERRUN`). The roadmap SC#3's wording ("MAIN / OVERTIME / OVERTIME ELAPSED") is satisfied semantically; `ROUND TIMER` is chosen over `MAIN` so plain 60/90/120 timers (which have no overtime) don't display jargon, and `OVERRUN` over `OVERTIME ELAPSED` per the locked CONTEXT decision and for glanceability.
- `+M:SS` prefix in count-up already comes from `useCountdown` `formatDisplay` (negative path). No format work needed — only label + band.
- Plain timers (`overtime_seconds === 0`) transition `main → countup` directly (no overtime band), which is correct and intended.
- `animate-pulse` on count-up is the one endorsed motion (locked: "count-up = red pulse"); consistent with the project's "no slow animations" rule (Tailwind pulse is a fast 2s loop, already shipped as `expired`).

## Interaction Contract — New Affordances

### 1. "80+20" duration preset (TIMER-01)
- Add a fourth chip to the picker in `src/components/AdminControls.tsx` alongside 60/90/120.
- Selecting it routes `duration_minutes = 80` + `overtime_seconds = 1200` (`overtimeMinutes = 20`) into `useGenerateRound` (already wired Phase 8).
- `data-testid="timer-duration-80-20"` (kebab-case). Selected state reuses the existing accent chip style; unselected reuses the neutral chip style.
- Picker may wrap to two rows on narrow mobile if four chips + label overflow; keep `flex-1` chips and `min-h-[36px]`.

### 2. "Start Timer" explicit start (TIMER-02)
- A round generated with 80+20 selected creates a **not-started** timer. The main 80-min countdown begins only when the admin presses **Start Timer**.
- Start Timer is a **primary accent** button (`bg-accent` … `min-h-[44px]`), icon `lucide-react` `Play`, label `Start Timer`. (Reusing `Play` is safe: not-started and paused-resume states are mutually exclusive.)
- `data-testid="timer-start-btn"`. Gated by the existing passphrase flow; on invalid passphrase reuse `INVALID_PASSPHRASE_RETRY_MESSAGE`.
- Placement: surfaced on/adjacent to the not-started timer card so it reads as "this round's clock is ready." (The engine representation of not-started is a RESEARCH/planning concern; the UI only needs a not-started timer to render the card state below and a start mutation to call.)

### 3. Not-started timer card state (new)
When a not-started 80+20 timer exists, `TimerDisplay` (or a sibling) shows:
- Numerals: the static main duration `80:00`, neutral style, **not ticking**.
- Band: neutral `bg-surface-raised text-text-secondary border-border` (no urgency, no pulse).
- Status label: `READY TO START`.
- The `Start Timer` primary button directly below.
- `data-testid="timer-display"` with `data-phase="not-started"` (or omit phase attr until started); `data-testid="timer-status"` text `READY TO START`.

### 4. Controls across all phases (TIMER-07)
- Pause / Resume / +5 min / Cancel in `src/components/TimerControls.tsx` must operate in `main`, `overtime`, and `countup`. No style changes required to the buttons themselves (neutral surface controls; Cancel stays `border-error/40 text-error`).
- Pause in overtime/count-up must visually freeze the active band (apply `opacity-70` + `PAUSED` label) without losing the phase color.
