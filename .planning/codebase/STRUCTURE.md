## Directory Purposes

**`src/pages/`:**
- Purpose: Route-level entry components — one file per URL route
- Contains: `LandingPage.tsx` (`/`) and `EventPage.tsx` (`/event/:eventId`)
- Key files: `src/pages/EventPage.tsx` (the main event orchestrator — most complexity lives here)

**`src/components/`:**
- Purpose: Reusable UI components — presentational and locally stateful
- Contains: 18 component files, each with a co-located `.test.tsx`
- Key files: `AdminControls.tsx` (round generation, timer start, end event), `PodCard.tsx` (pod display), `TimerDisplay.tsx` (countdown)

**`src/hooks/`:**
- Purpose: All data access and side-effect logic; components never call Supabase directly
- Contains: 24 hook files, each with a co-located `.test.ts`
- Key files: `useEventChannel.ts` (Realtime), `useGenerateRound.ts`, `useCountdown.ts`

**`src/lib/`:**
- Purpose: Module-level singletons and pure utility functions
- Contains: 4 source files + their tests + one integration test
- Key files: `pod-algorithm.ts` (the core algorithm — 470 lines), `supabase.ts` (Supabase client)

**`src/types/`:**
- Purpose: Shared TypeScript type definitions for DB entities
- Contains: `database.ts` only — defines `Event`, `Player`, `Round`, `Pod`, `PodPlayer`, `RoundTimer`
- Not: generated types (hand-written from schema knowledge)

**`src/test/`:**
- Purpose: Vitest test setup only
- Contains: `setup.ts` — imports `@testing-library/jest-dom` matchers

**`cypress/e2e/`:**
- Purpose: End-to-end spec files — one per feature flow
- Contains: 14 spec files (`.cy.js`)
- All specs use `cy.intercept()` to stub Supabase REST/RPC calls

**`cypress/fixtures/`:**
- Purpose: JSON response stubs for `cy.intercept()` calls
- Contains: `event.json`, `players.json`, `pods.json`, `pods-of-3.json`, `rounds.json`, `timer.json`, `error-duplicate.json`

**`supabase/migrations/`:**
- Purpose: Ordered SQL migrations applied to the Supabase project
- Generated: No — hand-written
- Committed: Yes — source of truth for DB schema

## Key File Locations

**Entry Points:**
- `src/main.tsx`: Bootstrap — mounts React app
- `index.html`: HTML shell with `<div id="root">`

**Configuration:**
- `vite.config.ts`: Build config, Vitest config, `@` path alias
- `tsconfig.app.json`: TS config for source files
- `cypress.config.js`: Cypress baseUrl and spec pattern
- `stryker.config.mjs`: Mutation testing scope and runner
- `eslint.config.js`: Linting rules including Cypress scoped config
- `.lintstagedrc.json`: Pre-commit lint-staged config

**Core Logic:**
- `src/lib/pod-algorithm.ts`: Pod generation algorithm (pure function, fully exported helpers)
- `src/lib/supabase.ts`: Supabase singleton (with Realtime worker + heartbeat)
- `src/lib/query-client.ts`: React Query singleton (staleTime=30s, retry=2)
- `src/lib/player-identity.ts`: localStorage key helpers (`podforge_player_{eventId}`)

**Database Schema:**
- `supabase/migrations/00001_initial_schema.sql`: events + players tables, RLS, create_event, drop_player
- `supabase/migrations/00002_rounds_pods_admin.sql`: rounds/pods/pod_players, admin RPCs
- `supabase/migrations/00004_timer_system.sql`: timer table + all timer RPCs

**Testing:**
- `src/test/setup.ts`: Vitest global setup
- `cypress/support/commands.js`: Custom Cypress commands
- `cypress/support/e2e.js`: Cypress support bootstrap

## Naming Conventions

**Files:**
- Components: `PascalCase.tsx` — e.g., `AdminControls.tsx`, `PodCard.tsx`
- Hooks: `useCamelCase.ts` — e.g., `useGenerateRound.ts`, `useAdminAuth.ts`
- Library utilities: `kebab-case.ts` — e.g., `pod-algorithm.ts`, `player-identity.ts`, `query-client.ts`
- Tests: same name + `.test.tsx` or `.test.ts` — e.g., `AdminControls.test.tsx`, `useTimer.test.ts`
- Integration tests: `{name}.integration.test.ts` — e.g., `pod-algorithm.integration.test.ts`
- Cypress specs: `kebab-case.cy.js` — e.g., `generate-round.cy.js`, `pods-of-3.cy.js`
- SQL migrations: `{sequence}_{description}.sql` — e.g., `00002_rounds_pods_admin.sql`

**Functions and Variables:**
- React components: `PascalCase` exported named function — e.g., `export function AdminControls(...)`
- Hooks: `useCamelCase` — e.g., `export function useGenerateRound(eventId: string)`
- Event handlers in components: `handleVerbNoun` — e.g., `handleGenerateRound`, `handlePassphraseSubmit`
- Query keys: string arrays, kebab-case nouns — e.g., `['players', eventId]`, `['currentRound', eventId]`

**Directories:**
- All lowercase, no hyphens: `pages`, `components`, `hooks`, `lib`, `types`, `test`

**Cypress data-testid attributes:**
- Pattern: `{component}-{element}-{modifier}` — e.g., `event-info-copy-btn`, `timer-pause-btn`, `admin-remove-player-{playerId}`
- Always `data-testid`, never classes or tag names in selectors

## Where to Add New Code

**New Page / Route:**
- Add component to `src/pages/NewPage.tsx`
- Add test to `src/pages/NewPage.test.tsx`
- Register route in `src/app.tsx` inside `createBrowserRouter`

**New UI Component:**
- Add to `src/components/NewComponent.tsx`
- Add test to `src/components/NewComponent.test.tsx`
- Import into the appropriate page or parent component

**New Supabase Query:**
- Add hook to `src/hooks/useNewThing.ts` using `useQuery` from `@tanstack/react-query`
- Add test to `src/hooks/useNewThing.test.ts`
- Register a query key in the hook's `queryKey` array (follow existing taxonomy)

**New Supabase Mutation:**
- Add hook to `src/hooks/useNewAction.ts` using `useMutation`
- Invalidate affected query keys in `onSuccess`
- Handle passphrase errors and `23505` duplicate errors in `onError`
- Add test to `src/hooks/useNewAction.test.ts`

**New DB Table or RPC:**
- Create `supabase/migrations/{next-seq}_{description}.sql`
- Add types to `src/types/database.ts`
- Add `useEventChannel` subscription in `src/hooks/useEventChannel.ts` if the table needs Realtime
- If filtering on a non-PK column in Realtime, add `ALTER TABLE {table} REPLICA IDENTITY FULL`

**New E2E Test:**
- Add spec to `cypress/e2e/new-feature.cy.js`
- Add fixture JSON to `cypress/fixtures/` if the test needs stub responses
- Use `cy.intercept()` to stub Supabase REST/RPC calls — do not call real backend in CI

**New Pure Utility:**
- Add to `src/lib/new-util.ts`
- Add test to `src/lib/new-util.test.ts`

**New Pod Algorithm Helper:**
- Add exported function to `src/lib/pod-algorithm.ts` (all helpers are exported for testability)
- Add unit tests to `src/lib/pod-algorithm.test.ts`
- Add integration scenarios to `src/lib/pod-algorithm.integration.test.ts`
